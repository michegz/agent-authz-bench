What this does not catch

  • 01

    This is a model, not a scanner. The call sequence is written by hand to show one defect and one fix. It is not a live agent deciding what to do, and it will not find holes in your API.

  • 02

    One endpoint is not an audit. Adding the check to cancel stops this path and nothing else. An API that hands a full waitlist with user IDs to any caller still has a disclosure problem after the cancel is fixed.

  • 03

    Ownership is not the only rule. A check that only asks "does this caller own this row" still permits anything they do own, at any rate, at any hour. Rate limits, business rules, and audit logging are separate controls.

  • 04

    Nothing here stops a compromised session. If an agent holds a real member's credentials, every call it makes is authorized. This control draws a line at other people's rows, not at whether the agent should be acting at all.

  • 05

    The waitlist on this page is invented. The user IDs, the positions, and the class are made up so you have something to click. No real gym, member, or booking system is represented.
